- **Enemies:** `EnemyDef.behavior` (MELEE, ARCHER, PACK, SHIELD, EXPLODER) picks the parts of `sim/sim_enemy.gd` that differ (`_approach`, what the windup ends in); recovery, stagger, poise, knockback and leash are shared. Archer: backs off under `preferred_distance`, the `windup` event carries the locked aim as a line (drawn by `EnemyView`) and the windup ends in an enemy `SimProjectile`. Wolf: spawns in packs (`SimEnemy.pack`, 3-4, one chase wakes the rest), circles, and the windup ends in a `lunge_distance` dash; a pack takes turns, one wolf winding up or recovering at a time (`SimEnemy._pack_busy`), and the windup sends the locked aim as a line, drawn by `EnemyView._draw_lane` as a lane `lunge_reach` to each side; stepping out of it dodges. Shield: `SimEnemy.facing` turns at `turn_speed` and goes to clients as a byte per shield in snapshot order (`Net.pack_facings`, `snapshot_for().facings`), where `EnemyView.facing` draws the arc and turns the sprite; `SimEnemy.blocks` stops light swings and arrows from the front (`block_pass` of the damage, `Net.EnemyEvent.BLOCK`); a heavy (`block_break` poise), magic (`SimProjectile.magic`, shockwave) or a hit from the side or back goes through. Exploder (`bloated_draugr`): `SimWorld.explode` hits players and pieces within `slam_radius` and kills it; killed in its windup it still explodes (`_hurt_enemy`). The spawner (`SimWorld._pick_kind`) picks by `EnemyDef.spawn_weight_day`/`_night`; `SimWorld.spawn_kind` pins one kind for tests. Wolves drop `meat` and `hide` (14 for the hide armor); kinds sharing a sheet use `EnemyDef.tint`. Snapshots' `Net.enemy_z` is now `kind + health`. Melee and shield draugr hit with a sweep (`EnemyDef.sweep_arc`, `SimEnemy._sweeps`): every player in the cone of the aim locked at windup start, sent as the windup's `line` plus `arc` (`Net.windup`) and drawn by `EnemyView._draw_cone`; stepping out to the side dodges it. Every behavior's closing-in step walks to `SimEnemy._waypoint` (the next point of its route), so all of them path around pieces.
- **Healing + magic:** the fire is a station (`cooked_meat`, `stewed_berries`, `hunter_stew`); `ItemDef.regen`/`regen_time` start a health regeneration on `SimPlayer` (`SimWorld.eat`, not saved), `ItemDef.heal` is the healing draught (H, `SimWorld.use_draught`, `Tuning.draught_cooldown`). A rune in the third equipment slot (`ItemDef.Slot.RUNE`, `ability`) grants an `AbilityDef` (`game/data/abilities/`) used on Q through `SimWorld.use_ability`: frost bolt (a `SimProjectile` with `slow`/`slow_time`, slowing `SimEnemy` via `slow_until`), healing ward (`SimWorld.wards`) and shockwave. `Net.status` sends cooldown and regen timers to the HUD, `Net.effect` the ward and shockwave visuals, slowed enemies are the negative z of `Net.enemy_z`. Runes drop from the barrow chest and king; shock and ward runes are crafted.

Without a store a chunk with a grave stays loaded (tests, balance sim); the survival bot walks back to loot (activity `grave`).
- **Terrain:** `world/terrain.gd` (`Terrain.Field`) gives every tile a level (sunken, ground, raised, shared per 4×4 `BLOCK`), a terrain byte (`LOWER_*`, `CLIFF`, `RAMP`) and face rows of south faces, returned by `WorldGen.chunk` as `levels`/`terrain`/`faces` (the client also asks for `looks`: `Terrain.looks_of` picks pieces of the tileset's 5×6 plateau, overhangs onto lower ground and stairs); levels are broad by construction (lattice + 3×3 cleanup, `tests/terrain_test.gd`), the spawn is flat within `FLAT_RADIUS`, a south face is `FACE_ROWS` tall and its lower `FACE_SOLID` rows block. ## Git workflow (early phase)

- **No PRs for now.** Commit straight to `main` and push. Session worktree branches get merged into `main` (fast-forward) and pushed; don't open a PR unless asked.
- **Semantic commits:** `type(scope): summary` (`feat`, `fix`, `docs`, `refactor`, `test`, `chore`, `perf`, `ci`), imperative, lowercase, no trailing period. Commits are authored as **r4b2**, with no AI co-author or attribution trailers.
- **Run the local check before every push:** `python tools/check.py` must end with "All checks passed" (it is also the pre-push hook; never skip it with `--no-verify`).
- **Watch `main`'s CI now and then**, at least after each push: `gh run list --branch main --limit 5`, and `gh run view <id> --log-failed` when one is red. A red `main` gets fixed before new work.
- **Milestones are tracked in `docs/PLAN.md` §8.** When work finishes a milestone, set its Status to Done (and the next one to Next) in the same push. Work that doesn't fit a planned milestone gets a lettered one inserted after the current one (M0a, M0b, …) with its own "done when", rather than renumbering.
- **Milestone releases:** when a milestone is done (its checks green in CI on `main`, short playtest done), bump the minor version over the latest tag, push the tag and write it into the Release column. The tag runs CI, which publishes a GitHub Release with the Linux and Windows zips:

      git tag -a v0.<n>.0 -m "M<x>: <name>" && git push origin v0.<n>.0

  GitHub starts no workflow for a push of more than three tags, so push them one per `git push` (or rerun with `gh workflow run CI --ref <tag>`; then check which release is marked Latest).
  Lettered milestones count too, so version numbers don't map 1:1 to milestone numbers. Patch tags (`v0.<n>.1`) for fixes between milestones.
- Renovate (`.github/renovate.json`) opens dependency PRs and automerges non-major updates once CI passes; those are the exception to "no PRs".

## Code conventions

- The server sim (`game/scripts/sim/`) is plain `RefCounted`, no scene tree; it only advances through `tick(delta)`. Tests build it directly.
- Client and server share one `Net` node at `/root/Main/Net`; all RPCs live there. Bump `Net.PROTOCOL_VERSION` on any RPC or payload change.
- Typed GDScript; tests in `game/tests/*_test.gd`. Commit the `*.gd.uid` files Godot generates next to scripts.
- Tools are one stdlib-only Python script each in `tools/`, run as `python tools/<name>.py` on Windows and Linux.
